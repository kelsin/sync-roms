# sync-roms

Tooling for syncing ROMs to and from storage: an S3 bucket (`roms.valefor.com`, region `us-east-1`) or a local folder such as a mounted share.

## Python environment

Always use `uv`; never bare `python`, `pip`, `pyenv` shims or a system interpreter (the pyenv `python` shim is broken here). `.python-version` pins the latest stable CPython (uv downloads it), `python-preference = "only-managed"` in `pyproject.toml` keeps uv off system pythons, and `uv.lock` plus the `dev` group (Pillow) cover every dependency the tests need. A SessionStart hook (`.claude/settings.json`) runs `uv sync` so each new session, worktrees included, gets a fresh `.venv`.

```bash
uv sync                                      # create/update .venv
uv run python -m unittest discover -s tests  # tests
uv run python tools/run_tests.py   # tests, in parallel processes (slow modules sharded, small ones batched)
uv run sync-roms ...                         # the CLI
```

A "module not found" error means the command skipped `uv run`, not that a package is missing: rerun it with `uv run`. Add dependencies with `uv add` (`uv add --dev` for test-only), never `pip install`. When a new stable Python is out, bump `.python-version`, run `uv sync` and the tests, and commit the result with `uv.lock`.

CI tests on Python 3.12 to 3.15 (`requires-python`), so code must run on 3.12 too.

## Tests

- A test module that imports `sync_roms` must import `isolate` first, directly or through `helpers`: it redirects HOME, XDG and the AWS settings to a throwaway folder and fails any test touching the real data folder or `~/.aws`.
- `tools/run_tests.py` batches small modules into one process each (and shards the slowest across several): modules in a batch share a process and its throwaway HOME, like the single-process `unittest discover` run.
- Tests start with no tags, ignore list or scraped names. Tags come from `helpers.storage_tags`.

## Storage access

Storage is the `root` setting (a folder, which wins) or the `bucket` setting (with an optional `endpoint`), each from a flag, a `ROMS_*` variable or `settings.json` (`usersettings.SETTINGS`). Nothing is hardcoded; the first run asks for either.

- **Never put backup or test files in storage.** No `.bak` copies, scratch uploads or test objects. Keep those local.
- Confirm with the user before any command that deletes or overwrites storage files (`rm`, `mv`, `sync --delete`).
- When storage is a bucket, always pass `--profile` to `aws`: `roms-readonly` by default, for anything that only reads; `roms` only when a write is actually needed. Preview a `sync` to the bucket with `--dryrun`, and add `--delete` only when explicitly asked.

## Commits and releases

Use [Conventional Commits](https://www.conventionalcommits.org) for every commit and for PR titles: `<type>[scope]: <description>` (`feat`, `fix`, `refactor`, `docs`, `chore`, ...), imperative and lowercase. Merge PRs with squash so the PR title becomes the commit message on `main`.

Releases belong to release-please: never hand-edit `__version__`, `CHANGELOG.md` or `.release-please-manifest.json`.

## CLI

- Every command is a subparser in `commands.build_parser`, listed in `commands.COMMANDS`, with its help in `cli.TOPICS` and its place in `cli.SUBCOMMANDS` (help and completion); their second words are in `commands.second_words`. Plain `sync-roms [CARD]` is `sync`; a bare word that is a command or an alias is that command, a path with a separator is a card. There are no mode flags: a new mode is a new command.
- Aliases (singular/plural and `umount`) are in `cli.ALIASES`, alias to main name; help and completion list main names only.
- `tests/test_readme.py` compares the README's Options table, Commands table (names and aliases), layout tables and Settings section with the parsers, `cli.SUBCOMMANDS`, `cli.ALIASES`, `layouts.json` and `commands.CONFIG_KINDS`.

## Data files

Only one storage layout is supported; don't add support for others. Repo data and personal data are never read from or written to storage. Never put a real game list in the repo. Repo files must not contain notes about storage's contents ("not in the bucket", "bucket has..."). Device notes say only why the systems were chosen, concisely.

### Reading and writing storage

- Storage code must work for a bucket and for a folder (`runtime.ROOT`): go through `s3.py`, `inventory.py` and `shared.py`, catch `s3.ERRORS`, and call `s3.check_root()` before treating a missing file as absent (an unmounted share must never read as empty storage).
- Ask only `inventory.py` what storage holds (keys, sizes, a bucket's ETags); never call `s3.list_sizes`/`stat_sizes`/`list_with_etags`/`list_folders` from elsewhere. It answers from `cache/storage-cache.json` (built by `sync-roms cache update`, patched by sync-roms's own writes in `s3.py`) and, without a cache of the storage in use, lists storage itself. `inventory.tag` (a file's ETag, or `<mtime_ns>-<size>` in a folder) and `shared.read` always read storage itself; other file contents come from the local mirror during a sync that uses one (`s3.read_root`).
- Before shared state is removed for a file the cache doesn't list (`scrape review`, `scrape clean`), `inventory.uncached` checks storage itself, so a file another machine added since the cache was built isn't taken for gone.
- `inventory.py`'s reads and `store.listed` leave ignored ROMs out, so nothing above them sees them. Ignoring a ROM never deletes its file.
- The shared JSON files (`ignored.json`, the scrape state in `scrape_state.py`, `variants-checked.json`, `tags.json`) go through `shared.py`: downloaded only when the storage tag differs from the local copy's (the ignore list once per run), and written by re-reading the storage file and applying only the write's own changes, so machines merge.
- "Mirror" means two things: the shared-file mirror, `~/.sync-roms/storage/` (those files at their storage path, their tags in `.tags.json`), and the local mirror, the `mirror` command's copy of what the cards reference (`mirroring.py`).
- `store.py`, `inventory.py` and `s3.py` import some modules inside functions because those modules import them back: a top-level import there is a circular import.
- Personal files are written with `store.write_json` (atomic): `cards.json` only through `store.write_cards` or `store.update_card`, and like `settings.json` and the overlay with `backup=True`. Write text files on a card with `cardfs.write_text` or `store.replace_file`.

`src/sync_roms/data/`, the same for everyone.

### Tags and collections

Tags come only from storage: `tags.json` at the storage root, read through `tags.py` (`shared.load`, once per run) and written only with `shared.update`, so machines merge; `~/.sync-roms/storage/` mirrors it. A tag put on a game by another machine appears after `sync-roms cache update`. `sync-roms check` validates the file.

`tags.json` is `{"tags", "games", "declined"}`. `tags` maps a tag id (a lowercase slug) to `{"name", "emoji", "description"?}`: name and emoji are required and an emoji belongs to one tag. `games` maps a bucket key (`<system>/<file>`) to `{"tags": [ids], "files"?, "variants"?}`: `files` are the other storage keys toggled with the game (a multi-disc game's discs; every write that creates a record for a playlist finds its discs in storage with `tags.discs`, as the lists fold them into the playlist's row (`listedit.playlist_groups`), so a game tagged again after losing its last tag gets them back; discs with no playlist are a row and a record each, with no files, and no file is ever another record's key), `variants` are `[{"bucket", "note"}]`. The system is the key's folder and titles come from `names.title`, so neither is stored. A record with no tags and no variants is removed. `declined` is `{key: [tag ids]}`: genre suggestions turned down. Tags only help find games: a tag never puts a game on a card.

A collection file (see Personal data) is `{"name", "description"?, "art"?, "games"}` (its games may carry a `note`) with its own loader and schema.

While `custom_collections` is on, sync writes every collection with a game on the card (in `collections` or not), each with only its games on the card.

Rules for tagged games:

- Every version of a game gets every tag that applies to it (regional releases, revisions, remasters, ports), so a tag filter finds each version. A game no tag fits stays untagged.
- A game's `variants`, `[{"bucket", "note"}]`, are related versions, the note saying in a few words what one adds. They're a note for the editors, which show them on the game's highlighted row, and `v` in the card editor adds one to the card; they're tagged like any other game.
- A compilation is tagged only when it holds a game no tag covers on its own.
- Tags are flat: no groups, categories or series. Make a group a tag of its own (`cave` and `shmups` are both tags).
- Every game list shows a game's tag emoji as its last column. `t` edits the highlighted game's tags (`n` adds a tag), `s` opens the tag filter (`Enter` cycles a tag off, required ✅, excluded 🚫; `c` clears it), and the card editor's own `s` opens all games narrowed by tags first. They live in `tagui.py` and `cardedit.py`.
- `sync-roms tags edit` (`tageditor.py`) edits tags and `sync-roms tags suggest [system ...]` (`tagsuggest.py`, `data/genre-tags.json`) suggests tags from scraped genres for every version of a game, saving the unchecked ones to `declined`. `tools/migrate_sets_to_tags.py` is the one-time script that made `tags.json` from the old set files.
- `tagui.FILTER` is the one process-wide tag filter, sticky across lists and never cleared but by `c` (`listedit.add_from_tag` sets it to its tag alone while its list is open, then restores the user's with `state`/`restore`, Ctrl-C included); tags deleted or merged leave it (`prune`, `retarget`).
- A list whose hidden rows would be acted on unseen opts out of it with `tag_filter=False` (the tag editor's own games and its add-from-a-system lists, a collection's own games, the `tags suggest` review) and says `tag filter paused here`.
- `T` bulk-tags the rows on screen: those the tag filter, the `/` search and the `V` view leave (`picker.on_screen`).
- Surprise picks only games with any of the tags in the `surprise_tags` setting, or in a card's own `surprise_tags` (card editor S menu), which wins; with neither it has no limit.
- `sync-roms check` notes tags with no games, one count per system of its untagged games (the pool `tags suggest` uses), `genre-tags.json` ids that aren't tags and a card's leftover `"sets"` key.

### Scraped names and metadata

- Editors and new game titles name MAME, FBNeo and PICO-8 sets through `names.title`: the scraped `name` from `scrapes/<system>/metadata.json`, else the file name (for pico8, without `.p8.png`). `names.py` keeps the scraped names in `cache/names.json` with each metadata file's storage tag and rereads one, from storage itself (never a mirror), only when its tag changes. Sync's own paths (`store.set_games`) keep file names.
- A metadata entry's optional `qualifier` sets it apart from other ROMs of the same name: its `name` is `<scraped name> (<qualifier>)`, before ` - Translated`, and re-scrapes keep it.
- `download pico8` (`bbs.py`) adds the BBS Featured carts to storage's `pico8/` under their BBS file names, upgrades newer revisions (renaming references in cards, surprises and collections), and keeps titles and authors in `scrapes/pico8/metadata.json`.
- PICO-8 is scraped (ScreenScraper system 234). A plain `scrape` also takes carts that have an entry but no `miximages`/`covers` picture in storage (unless ScreenScraper's last answer didn't offer miximages, until `--retry`). A scrape only adds to `scrapes/pico8/metadata.json`: it never changes a field the BBS (or an earlier scrape) already wrote.

It never deletes, overwrites or updates an installed port, its folder, saves or a runtime in `libs/`. For installed ports that need data (not `rtr`), it copies `os/portmaster/gamedata/<folder>/` into `Roms/PORTS/<folder>/` once (`portmaster_data`), never over a card file; ports with no data in storage, and picked ports not installed yet, go to `ports-needed.json` and a "Ports waiting for game data" block (instructions, where in storage the files go, `ports done`). Newer catalogue versions of installed ports are noted from the cached catalogue. `Roms/PORTS` is never swept, pruned, cleaned or copied into as a ROM folder (`portmaster.owns_folder`), and the `ports` system stays out of Surprise, collections, scrapes and card sizes on spruce (`portmaster.skip`); on other layouts it is hidden. `ports done` and `ports needed` refuse `--dry-run`.
- Guest cards (`guest: true`, set by `sync --guest` or the card editor's `F`, which turns it off too; `guest.py`) are friends' cards: a guest sync only copies ROMs, BIOS (its folder and `rom_files`) and scrapes (media, gamelists, a PICO-8 cart's own picture), and still runs `spruce_emu`, the end-of-run `clean` and the eject (not `hide_discs`: a loose disc is never recognized, so it stays where it is). Each guest sync seeds the card's `games` anew (`guest.recognized`: a storage ROM whose file is on the card under a matching name, case and Unicode form ignored, and storage's size; a same-named file of another size is never seeded or touched), dropping `excluded`, `collections`, `systems_off` and `surprises`; a dry run seeds in memory only. Nothing on the card is overwritten (`guest.new_files`; a gamelist gets an entry only for a ROM it has none for, and one that doesn't parse is left untouched with a warning), no renames or `card_moves` and no sweep (no `find_extras`, `prune_empty_systems`, legacy-folder cleanup), and the only deletions are the seeded ROMs the editor deselected (`guest.deletions`, at the card's own spelling, through the delete prompt; `--no-delete` keeps them; a system turned off with `x` is skipped, nothing copied (BIOS included) or deleted there) plus their media, named by `build_scrape_plan(..., all_media=True)` (every media job and text file, present ones too; stale media isn't swept). Their `<game>` entries are taken out of the system's gamelist too (`guest.remove_gamelist_entries`, only for ROMs that really went; a gamelist that doesn't parse is left with a warning), so a ROM added again later gets a fresh entry. It skips Surprise, `install_apps`, `onion_surprise`, `stage_spruce`, themes, APKs, drivers, `frontend_step`, `spruce_fixes.run`, `vita.add_psvita_files` and the Surprise budget warning. The guest state is read at the start, so turning it off in the editor mid-sync takes effect on the next sync; turning it on there reseeds and makes the sync a guest sync. Without an editor (`--yes`, `--json`, no terminal) the picks are the seed and nothing is deleted. `cards list` hides guest cards unless `--all`.
- `saves stash` and `apply` use Pickles' `MUOS/pickles/sram|state` on muOS (`muos_saves.py`), copied as they are; a Pickles stash applies only to muOS cards.
- `saves stash` and `apply` reach Android cards over adb through `android.py`, staging a temp copy (pushing back only what apply wrote).
- `config apply [CARD]` (`settings_apply.py`) applies a spruce card's settings (the spruce settings, WiFi and Syncthing steps of sync) without a sync, or over adb an Android device's (`android_settings.py`: APKs from `os/android/APKs/` the device lacks or has an older version of, by the rules in `android-apks.json` (never `dawn-zero`; GameNative and DroidDeck from the Retroid Pocket Nova's tier up; Eden where the device plays Switch; gba-ds on dual-screen devices; RAOfflineProxy when on for the card); RetroArch's `retroarch.cfg` `retroarch.json` settings, Syncthing save keys, folders and RetroAchievements from `ra_*`, the hotkeys from `hotkeys.json`, Cloud Sync off, `overlay_directory` set to the card's `Bezels/retroarch` when storage has bezels for the device (`bezels.files`); ES-DE's `<alternativeEmulator>` per system from `syncthing.json`'s `cores` and `esde_labels`, asking before restarting ES-DE, and skipping that part when declined), gives RAOfflineProxy All files access and a battery-optimization exemption when it is on for the card and installed (`android_access.py`), and, while `syncthing` is on, sets up Syncthing-Fork (`android_syncthing.py`): All files access, a battery-optimization exemption and, with `syncthing_server`, the server device and the two folders at RetroArch's save and state folders through its REST API over `adb forward`, the API key read from its export `backups/syncthing/config.zip` (a missing or encrypted export, a stale key or a stopped app warns and skips the folders). For an `emudeck` card (CARD is the folder holding `Emulation/`, or the current folder; a bare name only finds `/Volumes/<name>`) it runs on the Steam Deck or Steam Machine itself (`steamos_settings.py`): `cfg_wanted(platform="steamos")` in `~/.var/app/org.libretro.RetroArch/config/retroarch/retroarch.cfg` (missing: warned, RetroArch and Syncthing skipped; RetroArch open: waits with a prompt, fails without a terminal), the `<alternativeEmulator>` in the gamelists of `frontend.esde_dir("emudeck", base)` (skipped with `frontend.emudeck_problem`'s reason; asked first, default no, while ES-DE runs), warnings for EmuDeck's Cloud Saves (`cloud_sync_status=true` in the `settings.sh` EmuDeck reads) and per-core overrides (`<ra dir>/config/<core>/*.cfg`) setting `savefile_directory`/`savestate_directory`, then `steamos_syncthing.apply` with the save and state folders' real paths. `--dry-run` lists every setting, changed or not.

### Theme art data

`src/sync_roms/data/themes/art-book-next/` holds:

- `art.json`: the art ids, one per tag id among them (`surprise` has art too); a tag record holds no art, collections pick it.
- `art/<id>.png`, drawn by `tools/gen_theme_art.py`, with a generated `art/README.md` gallery for GitHub that sync never copies.
- `art-box/Imgs|Imgs_med|Imgs_small/<id>.png`: retro game boxes for SpruceOS, 336x480, 210x300 and 140x200, drawn by `tools/gen_box_art.py` from `sprites/<id>.txt` (32x32 pixel sprites, colours in `box-palette.json`) with the art's title in `box-font.json` and a badge picked by the id's hash. Run it after changing a sprite and commit both.
- `../totk-james/collections/Imgs|Imgs_med|Imgs_small/<id>.png`: ToTK-style collection art (gold glowing outline drawings from `gen_theme_art.py` on the theme's swirl card, title in its HYLIA font), 336x480, 210x300 and 140x200 128-colour palette PNGs, drawn by `tools/gen_zelda_art.py` (reads HYLIA from the ToTK theme in storage). Sync uses it instead of `art-box/` on `spruce` cards whose `spruce_theme` is `ToTK`, `ToTK - James` or `ToTK - Kelsin`. Run it after changing a drawing or a title and commit both.
- `emoji.json`: each art id's own emoji, for the editors.
- `logo-font.json`: the logo font's outlines (OFL).

With the card's `theme` on, sync copies the art into the copy of the theme in ES-DE's folder (the theme itself is a GitHub archive in `os/esde/themes/`, refreshed by `sync-roms themes update`), the theme customizations (Knulli, ROCKNIX), `MUOS/info/catalogue/Collection/box|grid` (muOS) or `Collections/Imgs/<name>.png` plus `Imgs_med/` and `Imgs_small/` from `art-box/`, or `totk-james/collections/` when the card's `spruce_theme` is a ToTK theme (Spruce: PyUI shows them by exact name, PNG only, never QOI; the theme plays no part).

The names sync gave art are listed in the theme copy's `.sync-roms-collections` (ES-DE; not ROCKNIX's staging folder of that name) or in `.sync-roms-art` (Knulli, ROCKNIX, muOS), and only those lose their art (on Knulli their `subset.<name>.*` settings too) when the collection or its art goes; on Spruce, only the collections sync owns do. With no art left to add, the theme isn't copied for that. With `--no-delete`, a retired collection's file or entry, its art and (Knulli) settings stay, its name stays in `frontend_collections` (`plan["kept"]`, listed with `list_kept`) and a later sync without the flag removes them. A theme update that ships metadata for a listed name takes it off the ES-DE list (the theme's from then on, never removed).

## Theme art

Rules for changing or adding a picture in `tools/gen_theme_art.py` (`uv run python tools/gen_theme_art.py [id ...]`). The reference is the theme's own Outline set, `_inc/systems/artwork-outline/*.png` in the archive in storage's `os/esde/themes/`: steady off-white lines about 6px wide with a slightly rough edge, corners joined, shapes closed, nothing drawn through a shape in front of it.

Lines:

- No wobble. Never add drift, jitter or varying thickness to "look hand-drawn"; it reads as loose and messy. The rough edge in `_ink` is the only texture.
- Every line end must land on another stroke, run off the band, or be an obviously free mark (impact dashes, a motion trail, a dashed path). An end that stops a few units short of an outline, or pokes past it, is the main thing that looks messy.
- Don't hand-pick the point where a detail meets a curved outline. Draw the detail too long inside `with p.inside(shape):` and it is cut at the outline.
- Overlap is drawn back to front: the shape in front gets `opaque=True` and hides what is behind it. Don't leave gaps in the back shape by hand, and never let lines cross through a front shape.
- A line may end on a straight edge at computed coordinates, but stay clear of that edge's rounded corners (the corner radius, in units, from each vertex).
- Prefer `arc`, `rounded` polygons and `mirror` of one half over a closed `spline` through a few points, which comes out lumpy. Use `spline` for open curves and for outlines with ten or so evenly spaced points.
- Close shapes. An open-ended fin, flame, cuff or body looks unfinished.

Size and placement:

- Drawings live in a box of about -50..50 units, y down, 3.3px per unit; the stroke is about 1.8 units wide, so keep parallel lines and small details at least 5 units apart. A solid dot is two small concentric circles (radius about 2.2 and 0.8). A larger solid shape, like the eye in `sonic`, is `p.fill(shape)`; keep it to one small feature of a picture.
- The band is slanted and about 340px wide where the picture sits, and `CENTER` is right of its middle. A picture wider than about 75 units runs off the band's right edge, and that look is wanted: the theme's own pictures are cut off on the right, and about 30 of ours lose 10 to 40px there. Don't move or shrink a picture to keep it whole on the right; give a wide one 10 to 20px of cut rather than letting it just touch the edge. Use a smaller `scale` and a negative x offset in `ART` only when more than about 40px would go, and keep the left edge clear.

Subject:

- One picture per meaning. Before adding one, check `art.json` for an entry that already means the same thing (a genre and a tag of the same genre, two kinds of fist). If two exist, ask which to keep; the kept picture goes under the tag's id, and the other id is removed from `ART`, `art.json`, `emoji.json`, `art/`, `sprites/`, `art-box/` and the tests.
- Draw the thing from the games, not a real-world lookalike: a console light gun (long thin barrel, boxy body, cable), not a pistol.
- A series may get its character when asked. Get the proportions of the right form: Pikachu has long slim ears with a short tip band, a head smaller than its chubby body, small solid eyes and a large stepped tail; wide triangular ears on a big head is Pichu.
- When asked to redo a picture without a subject, say which subject was chosen. When two concepts are equally plausible, show both and let the user pick.

Sprites (`sprites/<id>.txt`, the box art's picture, rendered by `tools/gen_box_art.py`):

- 32x32 with a clear border, `K` for the outline, lit from the top left, 2 to 3 tones per colour, and standing out against the id's box colour.
- Clean lines: symmetric shapes exactly mirrored, straight and diagonal edges in regular 1:1, 2:1 or 1:2 pixel steps, curves stepping evenly, one-pixel outlines with no jogs or stray pixels. Crooked sprites are rejected.
- Before finishing, enlarge a contact sheet (`gen_box_art.py --sheet`) and look at it.

Checking:

- Never finish without looking at the result. Read the generated PNG (the drawing is in y 600..1050), and also crop that part and enlarge it 2x to check every join, line end and overlap.
- Compare with the pictures next to it in a contact sheet of all of `art/`, and show the user that sheet or the changed pictures. Keep review images out of the commit.
- The tests check that every `art.json` id has a PNG in `art/`, a sprite (and no sprite lacks an id), the three `art-box/` sizes (equal to what the sprite renders to), the three `totk-james/collections/` sizes and its own emoji.

## Setup guide

`src/sync_roms/data/setup-guide.html` (`sync-roms guide` opens it in a browser) is the user's own record of the steps they take by hand to set up a device after sync-roms writes its card: installing apps, the ES-DE, Knulli and RetroArch settings they change, and the standalone emulators they use (where each is installed from and its settings). It is one self-contained page (no external files, scripts or fonts) that works opened straight from disk; picking a device and layout at the top shows only the steps that apply.

- Content lives in the `SECTIONS` array in the page's script. Sections, items and emulators take an optional `when` filter: `platform` (from `platformOf`: an `esde` card is Android, except `windows-pc`), `layout`, `systems` (the device supports any listed system), `tier`, `power` (`low`/`mid`/`high`/`desktop`, grouped from the tier in `POWER`), `device`, `dualscreen` (true with `screen2`), `gpu` (true with a `gpu` id), `network` (true unless the device has `"network": false`) and `bezels` (true when the device is in the `bezels-data` block, which `sync-roms guide` fills from `bezels.devices()` in the copy it opens, `[]` in the repo: the repo never names which devices have bezels). The Shaders section's picks live in `SHADER_CATEGORIES` (a preset and a Knulli Shader Set per power level). The RetroAchievements section holds login settings, never credentials. The Android "Standalone emulators" and "RAOfflineProxy" sections come from the systems each device supports.
- Only write steps and settings the user gave. Leave a section empty rather than guess which apps or settings they use.
- The page embeds each device's `id`, `name`, `soc`, `screen`, `screen2`, `firmwares`, `gpu` and `network` from `devices.json`, and its tier and systems (the tier chain of `device-systems.json` resolved, repo defaults only). After changing either file, run `uv run python tools/update_setup_guide.py`; `tests/test_setup_guide.py` fails when they differ.
