# ROCKNIX Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `rocknix` as a ninth layout with every feature that has a ROCKNIX equivalent.

**Architecture:** Data first (`layouts.json`, `systems.json`, `devices.json`), then explicit `rocknix` branches where code falls through to Knulli's behavior today (`scrape_plan.py`, `frontend.py`, `themeart.py`, `convert.py`). Anything that must land on ROCKNIX's internal storage (collections, RAOfflineProxy) is shipped as a script in `<card>/roms/ports/`, run once on the device.

**Tech Stack:** Python (run everything with `uv run`), unittest, JSON data files.

**Spec:** `docs/superpowers/specs/2026-11-20-rocknix-design.md`

## Global Constraints

- Run Python only through `uv run`; tests: `uv run python -m unittest discover -s tests`.
- Conventional Commits, imperative, lowercase (`feat(rocknix): ...`).
- Never put bucket-content notes in repo files; device notes say only why systems were chosen.
- Never put real game lists in the repo.
- Every system's `folders` dict has a `rocknix` key placed **before** `nextui` (`tests/test_nextui_data.py` requires `nextui` last); `null` where ROCKNIX has no system.
- `rocknix` is never the first (default) firmware of a device.
- Nothing is written to ROCKNIX's internal storage by sync; only to the games card.
- After changing `devices.json` or `systems.json`: `uv run python tools/update_setup_guide.py`.
- The spec's "Left to the builder" items are verified against ROCKNIX source (`github.com/ROCKNIX/distribution`, branch `next`) and the result noted in the commit message.

## Review Focus

- A system ROCKNIX only ships on some SoCs: its folder is still listed (sync can't know the SoC); a system ROCKNIX lacks entirely is `null` and is skipped, not crashed on.
- A card with no ROMs for a system whose folder ROCKNIX creates itself: sync creates the folder, doesn't fail.
- A save beside the ROM (`.srm` in the ROM folder) when the ROM folder has subfolders or the same stem in two systems: stash/apply attribute it to the right system.
- Collections containing a ROM path with `'`, `&` or spaces: the `.cfg` line is written verbatim as `/storage/roms/<folder>/<rel>` and the install script copes with spaces.
- Re-running the Ports install scripts after they deleted themselves: sync re-copies only when the storage file name changed or the card's copy is missing, and never overwrites a half-run state.
