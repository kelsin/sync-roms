# `sync-roms flash` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `sync-roms flash` command that writes a Knulli image from storage's `os/` to an SD card and verifies it.

**Architecture:** One new module, `src/sync_roms/flash.py`: pure helpers (image matching, disk filtering), a
streaming writer/verifier around `sudo dd`, and `run(args)`, which ties the pickers, the download, the write, the
check and the clean-up together. Wired into the CLI like `download pico8`.

**Tech Stack:** Python stdlib (`gzip`, `hashlib`, `plistlib`, `subprocess`, `tempfile`), the existing `picker`,
`ui`, `inventory`, `s3`, `store` modules, macOS `diskutil`/`dd`/`sync`. Tests use `unittest` (`python -m unittest discover -s tests`).

**Spec:** `docs/superpowers/specs/2026-11-19-flash-design.md`

## Global Constraints

- macOS only: on any other platform `flash` fails with a message and writes nothing.
- Only images matching `os/knulli-*.img.gz` in storage; listed through `inventory.files("os/")`, never `s3.list_*`.
- Nothing is written to storage or `~/.sync-roms/`.
- Write: `sudo dd of=/dev/rdiskN bs=4m`, fed decompressed 4 MiB chunks from the local `.gz`. No decompressed copy on disk.
- Check: `sudo dd if=/dev/rdiskN bs=16m`, exactly the bytes written, SHA-256 compared. Full read-back only, no `--quick`.
- Only `diskutil list -plist external physical` disks are offered, never the disk holding the temp folder or the
  storage root. The user must type the disk id exactly to go on.
- Clean-up always runs: kill a running `dd`, remove the temp folder, `sync`, then `diskutil eject` on success or
  `diskutil unmountDisk` after a failure or Ctrl-C.
- Commit messages use Conventional Commits, with no AI attribution or `Co-Authored-By` trailers.

## Review Focus

1. The `sudo` timestamp expires during a long download (default 5 min). Expected: the password is asked again before
   the write, not in the middle of a progress line. `sudo -v` runs before each `dd`. Task 4 tests the order of calls.
2. The card is pulled out or `dd` dies mid-write. Expected: the run reports a failed flash with `dd`'s error and a
   non-zero exit, the temp folder is gone, and nothing says it succeeded. Task 3 (dd failure) and Task 4 (clean-up).
3. The card is smaller than the image. `dd` fails with "No space left". Same expectation as 2. Task 3.
4. The user types `Disk4`, ` disk4 ` or `y` at the confirmation. Only the exact id (whitespace stripped) goes on. Task 4.
5. Not enough free space in the temp folder for the `.gz`. Expected: the run stops before downloading. Task 4.

### Task 1: Image list and device matching

**Files:**
- Create: `src/sync_roms/flash.py`
- Test: `tests/test_flash.py`

**Interfaces:**
- Produces:
  - `PREFIX = "os/"`
  - `knulli_devices(devices: list[dict]) -> list[dict]`: devices whose `firmwares` include `"knulli"`, in input order.
  - `images(listing: dict[str, int]) -> list[str]`: keys of the form `os/knulli-*.img.gz` (directly in `os/`, no subfolders).
  - `sort_images(keys: list[str], device_id: str) -> list[tuple[str, bool]]`: `(key, matches)`. Matches first, newest
    date first within each group, then by name.

Matching: from the image name, take the part between the chip (`h700`, `rk3568`, ...: the second dash-separated
token) and the trailing `-<codename>-<YYYYMMDD>.img.gz`, and drop dashes (`rg35xx-h` → `rg35xxh`). From the device
id, drop the vendor prefix (the first token) and dashes (`anbernic-rg35xxh` → `rg35xxh`, `miyoo-flip` → `flip`).
It matches when they are equal, or when the image part equals the device id with dashes removed (`miyooflip`).
The date is the last 8-digit run in the name.

### Task 2: SD card discovery

**Files:**
- Modify: `src/sync_roms/flash.py`

**Interfaces:**
- Produces:
  - `Disk = collections.namedtuple("Disk", "id size name")`: `id` like `"disk4"`, `size` in bytes, `name` the media name.
  - `parse_disks(listing: dict, info: Callable[[str], dict], exclude: set[str]) -> list[Disk]`: `listing` is the parsed
    plist of `diskutil list -plist external physical`. It takes `WholeDisks`, skips ids in `exclude`, and reads
    `TotalSize` (falling back to `Size`) and `MediaName` (falling back to `IORegistryEntryName`, then `""`) from `info(id)`.

  - `external_disks(exclude: set[str]) -> list[Disk]`: runs `diskutil list -plist external physical` and
    `diskutil info -plist <id>`, then `parse_disks`.

### Task 3: Streaming write and full read-back

**Files:**
- Modify: `src/sync_roms/flash.py`
- Test: `tests/test_flash.py`

**Interfaces:**
- Produces:
  - `DD = ["sudo", "dd"]` (tests patch it to `["dd"]`)
  - `raw(disk: str) -> str`: returns `f"/dev/r{disk}"` (tests patch it to a file path).
  - `class FlashError(Exception)`
  - `write_image(gz_path: str, disk: str, progress: Callable[[float], None] = None) -> tuple[int, str]`: starts
    `DD + [f"of={raw(disk)}", "bs=4m"]` with `stdin=PIPE`, `stderr=PIPE`. It reads `gzip.open(gz_path)` in 4 MiB
    chunks, writes each to `dd`'s stdin, and keeps the byte count and SHA-256. `progress` gets the fraction of the
    *compressed* file read (the underlying file's `tell()` / its size). Returns `(bytes written, hexdigest)`. Raises
    `FlashError` with `dd`'s stderr when `dd` exits non-zero or the pipe breaks (`BrokenPipeError`). On any
    exception, including `KeyboardInterrupt`, it kills `dd` and waits for it before re-raising.
  - `verify(disk: str, size: int, digest: str, progress: Callable[[float], None] = None) -> bool`: starts
    `DD + [f"if={raw(disk)}", "bs=16m", f"count={ceil(size / 16 MiB)}"]` with `stdout=PIPE`. It reads exactly `size`
    bytes into SHA-256, then closes stdout and terminates/waits `dd` (the extra bytes of the last block are discarded).
    Returns `False` if fewer than `size` bytes came back. On an exception it kills `dd` the same way.

The `bs=4m`/`bs=16m` spelling is accepted by both macOS and GNU `dd`, so the tests run anywhere.

- [ ] **Step 1: Write the failing tests** (`setUp`: a temp dir; patch `flash.DD` to `["dd"]` and `flash.raw` to
  `lambda d: self.target`; build the image as `os.urandom(5 * 1024 * 1024 + 123)` gzipped to `img.gz`):

```python
def test_write_then_verify_round_trip(self):
    size, digest = flash.write_image(self.gz, "disk9")
    self.assertEqual(size, len(self.data))
    self.assertEqual(digest, hashlib.sha256(self.data).hexdigest())
    self.assertTrue(flash.verify("disk9", size, digest))

def test_verify_ignores_bytes_past_image(self):
    size, digest = flash.write_image(self.gz, "disk9")
    with open(self.target, "ab") as f:
        f.write(b"x" * 1000)
    self.assertTrue(flash.verify("disk9", size, digest))

def test_verify_detects_corruption(self):
    size, digest = flash.write_image(self.gz, "disk9")
    with open(self.target, "r+b") as f:
        f.seek(3 * 1024 * 1024); f.write(b"\0")  # make sure it differs: flip the byte instead if it was 0
    self.assertFalse(flash.verify("disk9", size, digest))

def test_verify_short_read_is_false(self):
    size, digest = flash.write_image(self.gz, "disk9")
    os.truncate(self.target, size - 10)
    self.assertFalse(flash.verify("disk9", size, digest))

def test_dd_failure_raises(self):
    with mock.patch.object(flash, "raw", lambda d: "/nonexistent-dir/x"):
        with self.assertRaises(flash.FlashError):
            flash.write_image(self.gz, "disk9")

def test_progress_reaches_one(self):
    seen = []
    flash.write_image(self.gz, "disk9", seen.append)
    self.assertAlmostEqual(seen[-1], 1.0)
```

### Task 4: The `flash` flow

**Files:**
- Modify: `src/sync_roms/flash.py`
- Test: `tests/test_flash.py`

**Interfaces:**
- Consumes: Tasks 1–3; `store.repo_json("devices")`, `inventory.files(PREFIX)`, `s3.download((key, path, size), callback)`,
  `picker.filter_list(title, labels, cursor=0, hint=...)` (returns an index or `None`), `ui.ask`, `ui.human_size`,
  `ui.ProgressBar`/`ui.ByteProgress` (or a single `\r` line in `ui` style), `usersettings.ensure_bucket()`, `runtime.ROOT`.
- Produces: `run(args) -> int`. `args.dry_run` is a bool. It returns 0 on a verified flash or on dry-run or Esc, and
  1 on any failure. A clear message is always printed with `ui.failure`/`ui.fail`.

Flow, in this order:
1. `sys.platform != "darwin"` → fail ("flash needs macOS"). Then `usersettings.ensure_bucket()`.
2. Device: `filter_list("🎯 Which device?", names)` over `knulli_devices`. Esc → return 0.
3. Image: `filter_list` over `sort_images(images(listing), device["id"])`. The label is the file name (without `os/`)
   plus its size, with a match marked (e.g. a `✓` or `extras=[("matches", "green")]`), and the cursor starts at 0.
   If there are no images, fail ("no Knulli images in storage's os/").
4. Temp folder: `tempfile.mkdtemp(prefix="sync-roms-flash-")`, created now so `disk_of` can exclude its disk.
   Everything from here on is inside the `try` whose `finally` is step 11, so every exit (including dry-run, a
   wrong confirmation and Esc) removes it.
   Card: `external_disks({disk_of(tmp), disk_of(runtime.ROOT)} - {None})`. If none, fail ("no SD card found").
   Pick with labels `"disk4  64.0 GB  SD Card Reader"`.
5. Print a warning that everything on `<id>` (`<size>`, `<name>`) will be erased, then
   `ui.ask(f"Type {id} to flash it: ").strip() == id`. Anything else → print "Not flashed" and return 1.
6. `args.dry_run` → print what would be downloaded and written, return 0. No download and no `sudo`.
7. Free space: if `shutil.disk_usage(tmp).free < gz size + 64 MiB`, fail before downloading.
8. `sudo -v`; download the `.gz` into `tmp` with progress.
9. `sudo -v`; `diskutil unmountDisk <id>`; `write_image` with progress.
10. `sync`; `diskutil unmountDisk <id>`; `sudo -v`; `verify` with progress. A mismatch is printed as a failed flash
    ("the card doesn't match the image: try again or use another card").
11. `finally`: `shutil.rmtree(tmp, ignore_errors=True)`; `sync`; `diskutil eject <id>` if verified, else
    `diskutil unmountDisk <id>` (only once a disk was chosen). Report "✅ Flashed and verified — safe to remove the card".

`write_image`/`verify` own killing `dd` (Task 3). All `subprocess.run` calls go through one helper,
`_run(cmd: list[str]) -> subprocess.CompletedProcess` (text, captured output, except `sudo -v`, which needs the
terminal), so tests patch a single function.
