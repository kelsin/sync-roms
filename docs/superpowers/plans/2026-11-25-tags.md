# Tags Replace Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace game sets (with their categories and series) by flat per-game tags stored in one shared
`tags.json`, shown as emoji in every game list, editable on any game row, filterable, suggested from scraped
genres, usable to limit Surprise, and validated by `check`.

**Architecture:** A new `tags.py` owns `tags.json` (storage root, shared through `shared.py` like `ignore.py`
owns `ignored.json`). A new `tagui.py` holds the editor pieces every list shares (emoji column, `t` tag
checklist, tag filter). Sets code (`setedit.py`, set I/O in `store.py`, whole-set sync, series) is removed once
nothing uses it. A one-time `tools/migrate_sets_to_tags.py` builds `tags.json` from the set files.

**Tech Stack:** Python (uv), unittest, the project's `picker.filter_list` TUI, `shared.py`/`inventory.py`.

**Spec:** `docs/superpowers/specs/2026-11-25-tags-design.md` (read it first). Approved classifier:
`docs/superpowers/notes/2026-11-25-tags-classify.py`.

## Global Constraints

- Always `uv run` (tests: `uv run python -m unittest discover -s tests`, run with stdin closed: `< /dev/null`).
- Conventional Commits, lowercase imperative; end every commit message with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `tags.json` lives at the storage root, key `"tags.json"`; read with `shared.load`, written only with
  `shared.update` (fresh re-read, apply only this run's change). Never touch storage from tests: use helpers.
- What storage holds is read only through `inventory.py`.
- No real game list, tag list or emoji table for real games in `src/` or `tests/` (the migration tool's
  alias/emoji tables of tag names are allowed in `tools/`, as tag names, not game lists).
- Game key = bucket key (`nes/Foo (USA).zip`); a key's system is the part before the first `/`.
- Titles come from `names.title(key)`; `tags.json` stores no titles.
- Every tag has a `name` and an `emoji`; emoji are unique across tags.
- Tags never put games on a card.
- Match the existing style: docstrings in the code's voice, no new abstractions beyond those named here.

## Review Focus

- No `tags.json` in storage yet (fresh storage, before migration): editors, sync and `check` work; lists show no
  tag column text; the first tag edit creates the file.
- Two machines edit tags at once: an edit made after another machine's write keeps both (the change is applied
  to storage's fresh copy, not the run's cached copy).
- A tagged key that is no longer in storage (renamed or deleted ROM): lists don't crash, `check` reports it.
- Deleting or merging a tag that `surprise_tags` (setting or card) or `declined` names: those references are
  dropped or moved too, never left dangling.
- Storage unmounted or a write failing while saving a tag from an editor: the editor shows the error and keeps
  running; the cached tags are unchanged.

Each line has its test in the owning task (marked **[RF]**).

**Interfaces:**
- Produces (all in `tags.py`):
  - `KEY = "tags.json"`
  - `parse(text) -> dict` / `dump(data) -> str`: data is `{"tags": {id: {"name", "emoji", "description"?,
    "art"?}}, "games": {key: {"tags": [ids], "files"?: [keys], "variants"?: [{"bucket","note","files"?}]}},
    "declined": {key: [ids]}}`. `parse` drops malformed parts (like `ignore._clean`) and raises `ValueError` on
    bad JSON. `dump` writes sorted, one game per line inside `"games"`, `"declined"` the same, trailing newline.
  - `load() -> dict` (cached once per run under a lock; `reset()` clears it).
  - `all_tags() -> dict[id, dict]`, `tags_of(key) -> list[id]` (sorted), `record(key) -> dict | None`.
  - `emoji_of(key) -> str`: the key's tags' emoji joined with no separator, in tag-name order; `""` when none.
    A key that is another record's `files` entry gets that record's emoji.
  - `games_with(required: set, excluded: set) -> set[key]`: record keys (and their `files`) having every
    required tag and none of the excluded.
  - `variant_index() -> (variants, parents)`: same shapes as `store.variant_index` today, from game records;
    `parents[v]["title"]` is `names.title(canonical key)`, `"system"` from the key.
  - Writes (each through `shared.update`, refreshing the cache with the result, returning the new data):
    `set_game_tags(key, ids)`, `define_tag(tag_id, fields)` (create or update), `rename_tag(old_id, new_id)`,
    `merge_tag(src_id, dst_id)`, `delete_tag(tag_id)`, `retarget(old_key, new_key)` (game key, `files`, variant
    buckets, `declined`), `decline(pairs: dict[key, list[id]])`, `set_variants(key, variants)`.
  - Rule in every write: a record with no tags and no variants is removed; `tags` may be empty only with variants.
  - `slug(name) -> str` (reuse `store.slug`).
- `tests/helpers.py`: `storage_tags(test, data, root=None)` modelled on `storage_sets`: writes `tags.json` (dict
  dumped with `tags.dump`, or exact text) into a storage folder wired as `runtime.ROOT` and resets the caches.

### Task 8: Genre suggestions and the untagged pool

**Files:**
- Create: `src/sync_roms/data/genre-tags.json`, `src/sync_roms/tagsuggest.py`
- Modify: `src/sync_roms/commands.py`, `src/sync_roms/cli.py` (`tags suggest [system ...]` parser, help, completion)
- Test: `tests/test_tagsuggest.py`, `tests/test_editor_data.py` (genre-tags.json shape)

**Interfaces:**
- Consumes: `tags.load`, `tags.set_game_tags`, `tags.decline`, `inventory.files`, `names.title`,
  `surprise.is_candidate`, scrape metadata via the same reader `cardedit.Metadata` uses.
- Produces:
  - `genre-tags.json`: `{ScreenScraper genre string: [tag ids]}`. Keys are matched against a ROM's `genre` in
    full, then its part before `" / "`. Build it from the distinct `genre` values in storage's
    `scrapes/*/metadata.json` mapped to the migrated tag ids (no game names).
  - `tagsuggest.pool(system) -> dict[key, title]`: one key per game among the system's storage keys that pass
    `surprise.is_candidate`: drop keys that are a record's key, `files` or variant bucket, and keys whose
    `names.title` equals a tagged record's title on that system; of the rest, one key per title (first in sort
    order).
  - `tagsuggest.untagged(system) -> int`: count of `pool(system)` keys with no record.
  - `tagsuggest.suggestions(systems) -> dict[key, list[id]]`: for every key in the pool and every tagged record
    key, genre-mapped tags the key lacks, minus `declined`, minus ids not in `all_tags()`.
  - `tags suggest`: toggle list grouped by tag (`"<emoji> <tag> — <system> — <title>"`), all checked; Enter
    adds checked ones (`set_game_tags`, one `shared.update` for the batch) and records unchecked ones with
    `decline`. Prints counts.
