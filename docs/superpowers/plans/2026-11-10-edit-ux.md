# Editor UX Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A system-first card editor with set filtering, search, a live card space budget and a per-ratio "recommended systems" highlight, with the personal core list removed.

**Architecture:** Add pure-data pieces first (recommended tier, size cache, budget), remove the core list from `store`/`edit`/`commands`, then rebuild the card editor on top of `picker.filter_list` and fold everything under one `sync-roms edit` main menu. Sizes come from a persistent per-system cache that is diffed against a cheap name listing.

**Tech Stack:** Python stdlib only (`curses`, `json`, `concurrent.futures`); existing `store`, `s3`, `scrape_plan`, `picker`, `edit`; tests under `tests/` (pytest, helpers in `tests/helpers.py`, `tests/isolate.py`).

**Spec:** `docs/superpowers/specs/2026-11-10-edit-ux-design.md`

## Global Constraints

- Only `curses` for the TUI; no new dependencies.
- Repo data files stay in `src/sync_roms/data/`; repo files hold no notes about bucket contents.
- Never put a real game list in the repo; `games.json` starter is removed with the core list.
- `device-systems.json` overlay semantics unchanged: it edits only the can-play list, never the recommended tier.
- Recommended systems keep `systems.json` order, highlighted only.
- Over budget warns, never blocks. No or unparseable card size shows used only.
- Ratios match by exact string; no ratio means never recommended by ratio.
- Dual-screen = device has a `screen2` field. Overrides: dual-screen adds `nds`,`3ds`,`n3ds`; `3:5` adds `fbneo`,`mame`,`nds`,`3ds`,`n3ds`; `1:1` adds `gb`,`gbc`.
- Size cache lives in `~/.sync-roms/`, keyed by storage source; spot-check 5 random files; refresh after 30 days; never block the UI on it.
- Conventional Commits, lowercase imperative; no AI attribution in messages.
- Always use `--profile roms-readonly` for any bucket read during manual checks; nothing is written to the bucket.

## Review Focus

- Card with zero picks and no size string: editor opens, header shows used 0, no crash.
- System with a `ratio` missing, or a device with no `screen`: no crash, nothing highlighted by ratio.
- A game picked directly and also in a picked set, or covered by `full_system`: counted once in the budget.
- Size cache file corrupt or from another source: ignored and rebuilt, never raises.
- NAS unreachable or a system folder missing while listing sizes: row shows "…" or 0, editor stays usable.

### Task 3: Persistent size cache

**Files:**
- Create: `src/sync_roms/sizecache.py`
- Test: `tests/test_sizecache.py`

**Interfaces:**
- Consumes: `s3.list_sizes(prefix, sizes=True)`, `s3.stat_sizes(keys)`, `s3.read_root()`, `s3.location()` (source key).
- Produces:
  - `sizecache.cached(prefix: str) -> dict[str, int] | None` (what is in the cache now, no I/O beyond the cache file)
  - `sizecache.refresh(prefix: str) -> dict[str, int]` blocking: name listing (`list_sizes(prefix, sizes=False)`), stat only new keys, drop removed, spot-check 5 random cached keys (any mismatch rebuilds the prefix), rebuild if older than 30 days; writes `~/.sync-roms/sizes.json`
  - `sizecache.refresh_async(prefix, on_done: Callable[[dict[str, int]], None]) -> threading.Thread`
  - Cache is keyed by `s3.location()`; a corrupt file or a different source is treated as empty.

- [ ] **Step 1: Write failing tests** with fake `s3` functions (monkeypatch): first refresh stats everything; second refresh with one added and one removed name stats only the added one; a changed size in a spot-check triggers a full rebuild; age > 30 days rebuilds (inject the clock); corrupt JSON and a different source key yield an empty start without raising; `refresh_async` calls `on_done` with the final dict.
- [ ] **Step 2: Run** → FAIL.
- [ ] **Step 3: Implement** `sizecache.py` per the Interfaces; write atomically with `store.write_json`.
- [ ] **Step 4: Run** `pytest tests/test_sizecache.py -v` → PASS; then `pytest -q`.
