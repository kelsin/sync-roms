# PICO-8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the official PICO-8 binary's installer inputs on every card that can use it, and add `sync-roms download pico8` to fill storage with the BBS Featured carts under their real titles.

**Architecture:** A new `pico8.py` picks storage's newest Raspberry Pi zip and sets up a card (copy the zip for installers, or extract two files for Onion/Allium), remembering the zip per card in `cards.json`. A new `bbs.py` parses the Lexaloffle BBS Featured listing, decides new/upgrade/skip against storage, and writes carts, metadata and renamed references. `names.py` learns pico8 titles from `scrapes/pico8/metadata.json`.

**Tech Stack:** Python 3 standard library (`zipfile`, `urllib` through `github.get`-style helper, `re`), `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-14-pico8-design.md`

## Global Constraints

- No PICO-8 version or zip file name in code: the zip is the newest `os/pico8/` file matching `pico-8_*_raspi.zip` by natural sort (digit runs compared as numbers).
- Storage contents are read only through `inventory.py`; writes go through `s3.put_file`, `s3.put_text`, `s3.delete_keys`, `s3.move_keys`.
- Nothing from the zip, and no real game list, goes in the repo.
- Card setup happens for every card on `esde`, `knulli`, `muos`, `onion`, `allium`, whether or not it syncs any pico8 games; `slot` and `emudeck` get nothing.
- BBS requests: one at a time, `User-Agent` `sync-roms/<version>` (no personal data), stop at the first HTTP error with a warning and keep what was already written.
- Run tests with `python -m unittest discover -s tests`. Commits use Conventional Commits, no AI attribution.

## Review Focus

- `os/pico8/` empty or missing: sync prints nothing PICO-8 related and doesn't touch the card or `cards.json`.
- A card with no games at all (sync's `"has nothing to sync"` early return in `cli.py`) still gets the PICO-8 setup.
- Knulli after the installer ran (zip gone, recorded name equals newest): no copy, and sync's extras check doesn't offer to delete `Splore.png` or the zip while it is there.
- A BBS cart file name with no `-<digits>` revision, or with digits in its base (`2048-3.p8.png`, `pico8tetris.p8.png`), is identified correctly.
- `download pico8` interrupted or failing mid-way: carts already uploaded keep their metadata (write `metadata.json` after each cart, not once at the end).
